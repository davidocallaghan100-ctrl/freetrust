# FreeTrust

**Purpose**: Production FreeTrust mobile/PWA marketplace at `freetrust.co`.

**Type**: production web app / PWA

**Status**: active

## What It Does

- Runs the FreeTrust community economy marketplace and mobile PWA.
- Provides marketplace, profiles, events, wallet, calendar, messaging, and community flows.
- Serves PWA metadata and app icons for installed mobile homescreen use.
- Organisation directory cards show an options menu to organisation owners/admins and platform admins, including edit and confirmed delete actions.
- Feed composer supports Spotify/link attachments and organisation `@slug` tagging; feed cards render Spotify embeds, link preview cards, clickable URLs, and organisation mention links.
- Photo posts support multi-photo upload (up to 10 images) and render as swipe/click carousel slides in the feed while keeping the first image backward-compatible in `feed_posts.media_url`.
- Photo upload on `/create` compresses client-side, uploads directly to Supabase Storage through an abortable REST request, and shows a clear timeout/error instead of leaving mobile users stuck on `Uploading…` indefinitely.
- `/create` photo, video, and short-video posts support optional text overlays with five popular styles — Classic, Story, Neon, Caption Bar, and Minimal — plus top/center/bottom placement. Overlay metadata is stored as hidden feed-post content markers and rendered over photo carousels and videos in `PostCard`, so no database migration or media re-encoding is required.
- Photo posts with a Spotify track show a small `🔊` speaker button in the photo corner and a green rotating song-title strip under the photo. Tapping the speaker never opens a large popup/card; it plays only a real available preview through a hidden HTML audio element. Spotify previews are used first, and `/api/spotify/search` + `/api/spotify/track` now fall back to a confident iTunes/Apple Music preview match when Spotify returns `preview_url:null` (for example David's `National Treasures · Drake` post). Tracks with no available preview show the song title only rather than fake audio. The old always-visible under-post Spotify iframe is intentionally hidden on photo posts because it looked like an unrelated box on mobile.
- Owner edit mode for photo posts includes an **Edit photos** section for deleting, reordering, replacing, and adding up to 10 photos; saving rewrites the hidden multi-photo marker in the caption and keeps `feed_posts.media_url` synced to the first/cover image. It also includes an **Edit music** section with Spotify search, selected-track display, remove button, and manual Spotify URL fallback. Saving updates both the post caption markers and `feed_posts.link_url`, while preserving existing multi-photo markers.
- Shared post pages at `/feed/[id]` publish direct Open Graph/Twitter preview images: photo posts use the post's Supabase image URL, while posts without a usable photo fall back to `https://freetrust.co/icons/icon-512x512.png`. Dynamic `/api/og` is intentionally not used for post previews until its empty-image response issue is repaired.
- The mobile bottom-right profile tab and top-left avatar are profile/page switchers for users who own or administer organisations. They load the local Supabase session first, call `/api/organisations/mine` with the session bearer token when available, then fall back to direct client-side membership/creator reads so mobile/PWA session-cookie races do not send admins to the sign-in profile screen. The switcher buttons open a menu for personal profile plus admin pages; choosing an item persists the selected identity, syncs both switchers through `freetrust:feed-identity-change`, updates the visible avatar/page label, and routes to `/profile` or `/organisations/[slugOrId]` even when the user starts on `/feed`.
- On the newsfeed, the right-side avatar in each post action row is a reaction/comment identity dropdown. It lists the personal profile plus managed organisation pages, persists the selected identity locally, and uses it for feed reactions and comments. When an organisation page is selected, reaction/comment API calls include `posted_as_organisation_id`, the server verifies the user is an owner/admin or creator before accepting it, and comments render with the organisation logo/name plus a Page badge.
- Newsfeed reactions show distinct per-type emoji/count chips (`Trust`, `Love`, `Insightful`, `Collab`) in a compact row above the action bar when reactions exist. The reaction picker also shows the current count for each emoji, and optimistic updates keep both the selected reaction and per-type counts in sync with `/api/feed/posts/[id]/react`.
- Feed post detail pages (`/feed/[id]`) hydrate the main post and the **More from this author** cards with the same live engagement side-table data as the main feed: per-type reaction counts, the current user's selected reaction, comment/save counts, saved state, top comment preview, organisation bylines, and owner controls. On mobile, the expanded main post renders edge-to-edge with no outer card border/radius or side gutter; the expanded photo/video media and soundtrack strip are full-bleed with pointed square corners. Desktop keeps the centered 640px detail column.
- Post owner options (`⋯`) are layered above the post type badge and body content on mobile: the header allows overflow while the menu is open, and the edit/delete dropdown uses a high z-index so the **Edit post** action is not hidden behind the `Photo` badge or post content.
- The post-row reaction/comment identity menu uses the `.ft-feed-identity-menu` mobile class so, on small screens, the personal/profile + admin-page switcher is fixed within the viewport with safe-area bottom spacing, no horizontal overflow, and its full admin/page section visible instead of clipped off-screen.

# FreeTrust

**Purpose**: Production FreeTrust mobile/PWA marketplace at `freetrust.co`.

**Type**: production web app / PWA

**Status**: active

## What It Does

- Runs the FreeTrust community economy marketplace and mobile PWA.
- Provides marketplace, profiles, events, wallet, calendar, messaging, and community flows.
- Serves PWA metadata and app icons for installed mobile homescreen use.
- Organisation directory cards show an options menu to organisation owners/admins and platform admins, including edit and confirmed delete actions.
- Feed composer supports Spotify/link attachments and organisation `@slug` tagging; feed cards render Spotify embeds, link preview cards, clickable URLs, and organisation mention links.
- Photo posts support multi-photo upload (up to 10 images) and render as swipe/click carousel slides in the feed while keeping the first image backward-compatible in `feed_posts.media_url`.
- Photo upload on `/create` compresses client-side, uploads directly to Supabase Storage through an abortable REST request, and shows a clear timeout/error instead of leaving mobile users stuck on `Uploading…` indefinitely.
- `/create` photo, video, and short-video posts support optional text overlays with five popular styles — Classic, Story, Neon, Caption Bar, and Minimal — plus top/center/bottom placement. Overlay metadata is stored as hidden feed-post content markers and rendered over photo carousels and videos in `PostCard`, so no database migration or media re-encoding is required.
- Photo posts with a Spotify track show a small `🔊` speaker button in the photo corner and a green rotating song-title strip under the photo. Tapping the speaker never opens a large popup/card; it plays only a real available preview through a hidden HTML audio element. Spotify previews are used first, and `/api/spotify/search` + `/api/spotify/track` now fall back to a confident iTunes/Apple Music preview match when Spotify returns `preview_url:null` (for example David's `National Treasures · Drake` post). Tracks with no available preview show the song title only rather than fake audio. The old always-visible under-post Spotify iframe is intentionally hidden on photo posts because it looked like an unrelated box on mobile.
- Owner edit mode for photo posts includes an **Edit photos** section for deleting, reordering, replacing, and adding up to 10 photos; saving rewrites the hidden multi-photo marker in the caption and keeps `feed_posts.media_url` synced to the first/cover image. It also includes an **Edit music** section with Spotify search, selected-track display, remove button, and manual Spotify URL fallback. Saving updates both the post caption markers and `feed_posts.link_url`, while preserving existing multi-photo markers.
- Shared post pages at `/feed/[id]` publish direct Open Graph/Twitter preview images: photo posts use the post's Supabase image URL, while posts without a usable photo fall back to `https://freetrust.co/icons/icon-512x512.png`. Dynamic `/api/og` is intentionally not used for post previews until its empty-image response issue is repaired.
- The mobile bottom-right profile tab and top-left avatar are profile/page switchers for users who own or administer organisations. They load the local Supabase session first, call `/api/organisations/mine` with the session bearer token when available, then fall back to direct client-side membership/creator reads so mobile/PWA session-cookie races do not send admins to the sign-in profile screen. The switcher buttons open a menu for personal profile plus admin pages; choosing an item persists the selected identity, syncs both switchers through `freetrust:feed-identity-change`, updates the visible avatar/page label, and routes to `/profile` or `/organisations/[slugOrId]` even when the user starts on `/feed`.
- On the newsfeed, the right-side avatar in each post action row is a reaction/comment identity dropdown. It lists the personal profile plus managed organisation pages, persists the selected identity locally, and uses it for feed reactions and comments. When an organisation page is selected, reaction/comment API calls include `posted_as_organisation_id`, the server verifies the user is an owner/admin or creator before accepting it, and comments render with the organisation logo/name plus a Page badge.
- Newsfeed reactions show distinct per-type emoji/count chips (`Trust`, `Love`, `Insightful`, `Collab`) in a compact row above the action bar when reactions exist. The reaction picker also shows the current count for each emoji, and optimistic updates keep both the selected reaction and per-type counts in sync with `/api/feed/posts/[id]/react`.
- Feed post detail pages (`/feed/[id]`) hydrate the main post and the **More from this author** cards with the same live engagement side-table data as the main feed: per-type reaction counts, the current user's selected reaction, comment/save counts, saved state, top comment preview, organisation bylines, and owner controls. On mobile, the expanded main post renders edge-to-edge with no outer card border/radius or side gutter; the expanded photo/video media and soundtrack strip are full-bleed with pointed square corners. Desktop keeps the centered 640px detail column.
- Post owner options (`⋯`) are layered above the post type badge and body content on mobile: the header allows overflow while the menu is open, and the edit/delete dropdown uses a high z-index so the **Edit post** action is not hidden behind the `Photo` badge or post content.
- The post-row reaction/comment identity menu uses the `.ft-feed-identity-menu` mobile class so, on small screens, the personal/profile + admin-page switcher is fixed within the viewport with safe-area bottom spacing, no horizontal overflow, and its full admin/page section visible instead of clipped off-screen. Its identity/page loading calls are timeout-guarded and have a hard fallback so the menu cannot stay indefinitely on `Loading your pages…`; when page lookup is slow or mobile auth temporarily fails, it still preserves and displays the currently selected admin/page identity from local storage while forcing a fresh page-list retry in the background.
- On mobile feed, post cards and post media are full-bleed to the left and right screen edges; composer/filter controls keep small horizontal padding. Photo media wrappers are explicitly classed so the mobile CSS removes the old inner media padding as well as the outer card padding.
- The newsfeed supports a mobile/PWA pull-down refresh gesture at the top of `/feed`, with a small “Pull to refresh / Release to refresh / Refreshing…” indicator; refresh fetches `/api/feed/posts` with `cache: 'no-store'` and resets pagination to page 1. Normal touch scrolling is left native, and Android stylus/S Pen drags have a pen-only fallback that scrolls the feed without hijacking buttons, links, or composer controls.
- Feed videos show a first-frame preview instead of a black box where the browser allows frame capture, and the video element falls back to its own loaded first frame when canvas capture is blocked. Videos and shorts auto-play muted once meaningfully visible in the feed, retry when the video can play, pause when scrolled away, and still allow manual tap-to-play/pause and mute/unmute. The mobile player uses taller cropped/fill frames (`object-fit: cover`) so vertical videos appear larger and avoid black side bars as much as browser video constraints allow.
- Services Marketplace loads active service listings through `/api/services/marketplace`, a no-store same-origin API backed by the server Supabase client, so the PWA refreshes real services on every visit instead of relying on stale client-side Supabase/browser state. Service category labels are normalised to category IDs on publish and browse so category filters keep showing the correct real listings.
- Organisation pages can now offer marketplace services and products. `listings.organisation_id` links an active listing to the organisation profile while `seller_id` remains the accountable human owner; `/seller/gigs/create?orgId=<org>` and `/products/new?orgId=<org>` preselect the managed organisation, and organisation profile pages show **Services**, **Products**, and **Posts** tabs. The organisation tab rail uses a fixed full-width underline with a separate horizontal scroller so touch-dragging tabs does not pull the line down into the section heading. Member profile pages also show real social feed posts in their **Posts** tab, while activity remains available separately. Feed music previews coordinate through a page-level playback event so starting a second post's soundtrack stops the first.
- Member profile pages use the same mobile-first profile rhythm as organisation pages: larger full-bleed cover, compact stat cards, and a horizontal tab rail for **Overview**, **Trust**, **Services**, **Products**, **Grassroots**, **Posts**, **Activity**, **Following**, and **Followers**. Overview now shows a real Instagram-style 3-column photo grid from the member's photo posts while keeping the full social feed in **Posts**; **Trust** holds profile completeness and Trust Economy. The photo grid header is action-only with compact `View posts` text and, on own profiles, a small grey/white `+` button; mobile tiles are full-bleed and use a portrait phone-photo ratio instead of square crops. Personal product listings appear in the **Products** tab, while organisation products remain shown in organisation profile **Products** tabs. Heavy profile data (services, products, grassroots listings, social posts, activity, and connection lists) is loaded only when its tab is opened so the initial personal profile view is lighter on mobile. On mobile, the personal avatar is pulled higher into the cover so the profile action buttons are not covered, and the name/meta section is tightened upward for a cleaner profile header. Own profiles show a small frame (`🖼️`) button in the cover-photo corner that opens cover-photo fit controls: rotate left/right, zoom in/out, horizontal focus, and vertical focus; these store presentation metadata on the profile (`cover_position_x`, `cover_position_y`, `cover_rotation`, `cover_scale`) without modifying the uploaded image. Stripe payout setup prompts now live in **Settings → Stripe Connect** instead of the profile Overview; incomplete Connect accounts show **Finish Stripe payout setup** there and link to `/seller/connect`.
- Member profiles support professional headline + professional experience and a defensible profile verification workflow. Members can submit verification notes/details from Edit Profile, which sets `verification_status='submitted'` and stores review evidence in `verification_details`; normal profile saves cannot grant `is_verified`, `verified_at`, or `verified_by`. Verified badges render only for profiles with `is_verified=true`, `verified_at`, or approved `verification_status='verified'` across the profile header, member directory, and feed author bylines. Additive schema support lives in `supabase/migrations/20260526093000_profile_verification_experience.sql`.
- Messages now route thread reads/sends through `/api/messages/[conversationId]` instead of direct browser inserts, so server-side participant checks, recipient existence checks, message length limits, basic per-user/conversation rate limiting, and off-platform-payment safety warnings apply consistently. The mobile thread UI follows the approved WhatsApp-like dark FreeTrust direction with a verified-member header, payments-stay-inside-FreeTrust safety chip, rounded chat bubbles, per-message timestamps/checkmarks, and a 16px pill composer to avoid iOS zoom. Product/service checkout no longer creates mock fallback orders when listings are missing; checkout rejects missing/unavailable listings, missing sellers, self-purchases, and invalid prices instead of defaulting seller/amount to the buyer.
- The public homepage and footer highlight FreeTrust security posture with protected conversations, on-platform payments, account-safety layers, clear policy links, and one compact **Legal** footer button that opens a full-screen slide-style legal library for 10 confidential documents. The hero globe now renders an instant CSS fallback globe while Mapbox initializes, then fades Mapbox in on load so first landing on mobile does not show a blank globe area. `/safety` is the Trust & Safety Policy page covering verified member trust, protected messaging, on-platform payments, marketplace integrity, moderation/reporting, data protection, prohibited behaviour, and safety reporting; it links alongside existing `/privacy` and `/terms` policy pages.
- Public event cards now show a branded event-poster fallback whenever an imported event has no usable external image, so the landing page and Events directory do not render blank calendar-only headers. PredictHQ source attribution text is stripped from event descriptions before display while preserving the real event description content.
- Newsfeed job cards attribute side-table jobs to the real organisation/company supplied by the job row. Organisation jobs render with the organisation byline, while externally ingested company jobs use explicit feed author display metadata so David's admin/system profile is not shown as the job owner in `/feed?filter=jobs`.
- The `/safety`, `/privacy`, and `/terms` policy pages share a cleaner dark policy layout with a contained hero, readable card stack/grid, pill policy links, and mobile-safe spacing inside the FreeTrust shell.
- Logged-out public navigation deliberately does not reuse cached personal/page identity. The feed composer shows **Sign in to post on FreeTrust**, the mobile bottom profile action links to `/login?redirect=%2Fprofile`, the mobile create button links to `/login?redirect=%2Fcreate`, and top/drawer account controls show sign-in/sign-up actions instead of David's private profile/page switcher. Browser-only cached identity keys (`ft_uid` and `freetrust.feed.identity.v1`) are cleared or ignored when there is no active Supabase user; production profile/org data is not deleted.
- New member signup now routes email, Google, and Apple OAuth users through the same `/onboarding?welcome=1` profile setup flow so they are prompted for face photo, bio, location, and hobbies before being treated as fully onboarded. `/auth/callback` sanitizes `next`, repairs/syncs OAuth profile rows with provider name/avatar metadata, redirects existing users with `onboarding_complete=false` back to onboarding, and falls back to `/auth/session` for Supabase fragment-token callbacks so users are not bounced to login after a valid provider sign-in.
- Login and registration now render equivalent configured social auth entry points while preserving email/password fallback. Apple and Google are enabled for production; Facebook and LinkedIn buttons remain feature-flagged behind `NEXT_PUBLIC_ENABLE_FACEBOOK_OAUTH` and `NEXT_PUBLIC_ENABLE_LINKEDIN_OIDC` until their Supabase provider credentials are configured. Google OAuth remains guarded against known in-app browser `disallowed_useragent` failures, and auth pages now allow vertical scrolling on smaller mobile screens so the provider list cannot be clipped.
- Service/gig publishing now guards UUID-only database columns from UI slug values: service category slugs stay represented through the `category` label fallback instead of being written to `listings.category_id`, and service radius is serialized safely for the current production schema. This prevents the Supabase “invalid input syntax for type uuid” upload failure across mobile and desktop service creation.
- The `/agents` page now surfaces 16 FreeTrust AI agents in four groups: **Research & plan**, **Create & earn**, **Win work**, and **Grow & connect**; the Translator agent is intentionally not registered or shown. Each agent card and run modal shows a clear name, description, credit cost, and use case; previously-hidden agents such as Bulk Listing Generator, Image Generator, Trust Score Optimiser, Pricing Adviser, Revenue Intelligence, Collab Matchmaker, and Content Repurposer are visible with examples. The page routes streaming agents through `/api/agents/stream`, uses a valid dated Claude Sonnet model ID, and prompts weak agents to return conservative actionable plans instead of placeholder or invented results. In the mobile drawer, Agents sits in its own **CREATE** section below **Early Investors → Investor Deck** with the 😎 icon.
- The FreeTrust Image Generator agent costs ₮50 and is handled by `/api/agents/run` with a dedicated safety-gated path: prompts are reviewed before any TrustCoins are debited, unsafe/unlawful requests are blocked without charge, generated images are reviewed again before upload, failed generation or post-generation safety failures refund ₮50, and only approved images are uploaded to the public `feed-media/ai-generated/<userId>/...` path with an optional confirmable **Post image to feed** action.
- The immersive `/agents` mobile hero shows all four primary clickable ideas at once — **Create a listing**, **Publish an event**, **Draft + send message**, and **Find buyers** — instead of hiding one off-screen in a carousel. Tapping a primary idea starts an agent chat immediately with a targeted follow-up question asking for the missing details before any model run or platform action happens.
- In active `/agents` chats, the hero/idea sections are hidden as soon as the user types or a conversation starts so the thread has the full viewport. The composer textarea is taller for mobile typing, and chat display/submitted prompts strip asterisks and hyphen/dash markers; backend agent prompts also instruct models to avoid Markdown bullets and asterisks/hyphen markers in user-facing prose.
- `/agents` routes public LinkedIn/social post, caption, launch, and announcement prompts to Content Repurposer while keeping direct messages/DMs/replies on Message Drafter. Content Repurposer now returns clean JSON fields that render as readable social drafts rather than raw JSON dumps, with editable `Prepare social draft` and optional `Post to FreeTrust feed` action cards; Message Drafter is explicitly scoped to one-to-one messages.
- `/dashboard/analytics` is the real-activity member analytics dashboard. It uses the FreeTrust logo/brand system, inline component styles, 7/30/90-day filters, KPI cards, growth and engagement charts, top content, recent activity, and empty states that show no fake/sample data. Its mobile layout uses viewport-aware single-column stacking and overflow guards so chart/content cards do not overlap under the FreeTrust mobile shell. Events are stored in `public.analytics_events` through the approved `20260614_analytics_events.sql` migration and are tracked from real profile, listing, post, enquiry, message, and follow activity; `/analytics` redirects to `/dashboard/analytics`.
- `/products` has a two-tab marketplace surface: existing **FreeTrust Listings** remains unchanged, while **🔍 Find Online** uses `/api/parse-search-intent` for shopping-query extraction, searches active product listings from `public.listings`, calls `/api/search-external` for SerpApi Google Shopping results, shows FreeTrust sellers beside live online retailer cards, and logs authenticated external buy-through clicks in `public.external_product_clicks`.
- `/products` FreeTrust Listings now also includes a self-refreshing external retailer catalogue sourced from SerpApi Google Shopping. Nightly Vercel cron `/api/cron/refresh-external-products` can request up to 100 real products per category across 27 expanded external categories; stale never-clicked products are demoted from trending rather than deleted. The listings grid keeps FreeTrust community listings first, then clearly labelled `🏪 Retailer` cards with `⚠ Not Trust Coin eligible`, an outlined teal retailer CTA, a FreeTrust exit modal with affiliate disclosure, and click logging/incrementing through `/api/external-products/click`. Retailer URLs are stored/logged raw; legacy FreeTrust referral UTM parameters are stripped in code, and Skimlinks wrapping happens only at outbound click time using publisher ID `304900X1793091` from `NEXT_PUBLIC_SKIMLINKS_PUBLISHER_ID`.
- `/products` now has a Supabase-backed persistent basket for both FreeTrust community listings and external retailer saves. The floating basket button appears only on the product marketplace, community items show subtotal + the shared `5% FreeTrust fee` and check out through a Stripe PaymentIntent via `/api/checkout/create-payment-intent`, while retailer saves remain clearly separated with `Complete on retailer site` actions and are never charged through FreeTrust. Basket operations use `/api/basket` so authenticated baskets survive logout/session changes; the Stripe webhook handles `type=product_basket` payment success by marking orders paid, transferring seller payouts through Stripe Connect, and clearing paid community basket items.

## Integrates With

- **Supabase**: auth and application data.
- **Vercel**: production deployment for `freetrust.co`.
- **Stripe**: payments and Apple Pay domain verification.
- **Google Calendar**: optional calendar integration.
- **SerpApi**: Google Shopping price comparison for the `/products` Find Online tab via `SERPAPI_KEY`.
- **Skimlinks**: affiliate wrapping for outbound retailer clicks via `NEXT_PUBLIC_SKIMLINKS_PUBLISHER_ID=304900X1793091`; the approval script is loaded globally from `app/layout.tsx`, and database storage/logging keeps raw retailer URLs rather than Skimlinks URLs.
